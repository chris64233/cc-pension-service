# cc-pension-service

参保人任职期间与养老待遇资料管理服务。

当前包含：任职期间登记与幂等控制、重叠期间折算、服务年限版本管理、
待遇核定快照、更正产生的新版本与新旧待遇差额台账，以及应用上下文测试。

## 开发环境

- JDK 21
- Maven Wrapper 3.9.9
- Spring Boot 4.1.1

迁移项目沿用现有 Spring Boot 版本，其他项目使用上述版本。

## 主要业务规则

### 期间登记

- 参保人可登记多个任职期间，每个期间包含单位、起止日期（闭区间）和计入比例。
- 计入比例取值范围为 (0, 1]，1 表示全额计入，不足 1 表示部分计入。
- 登记号在同一参保人下唯一，作为幂等键：重复提交相同登记号且内容一致时
  返回原登记结果；内容不一致时返回 409 冲突。

### 重叠处理与年限折算

- 同一日历日被多个期间覆盖时，当日计入比例取各期间比例之和并封顶 1.0，
  重叠部分不重复累计。
- 年限按自然日折算：年限 = 天数 × 当日有效比例 / 365，每个等比例分段
  保留 4 位小数（HALF_UP），累计年限为各分段之和。
- 所有金额与比例均使用 BigDecimal 计算。

### 版本管理

- 每次期间登记或更正，参保人的服务年限版本号单调递增 1。
- 更正不删除原期间，仅将其标记为在新版本被取代，历史版本可完整回放。

### 待遇核定

- 核定时锁定参保人当前服务年限版本，按该版本下的期间集合计算累计年限。
- 待遇基数取核定请求中的月平均工资（保留 2 位小数）；
  月待遇额 = 待遇基数 × 累计年限 × 1%（每年 1%）。
- 核定结果（版本号、累计年限、待遇基数、月待遇额、分段折算明细）形成
  不可修改的快照，系统不提供任何更新或删除入口。

### 追溯更正与差额台账

- 核定后发现历史期间错误时，通过更正记录产生新版本，再重新核定。
- 重新核定不覆盖原核定；系统自动计算新旧核定的月待遇差额并写入独立台账：
  差额为正为补发（SUPPLEMENT），为负为追回（RECOVERY），为零为 NONE。
- 台账按生成顺序链式挂接前后两笔核定，可完整追溯差额链。

### 并发控制

- 期间登记、更正与核定均先对参保人行加悲观写锁，同一参保人的版本推进
  与版本读取串行化：并发登记重叠期间不会产生重复年限；核定与更正并发时，
  核定只使用一个完整、一致的版本。
- 登记号唯一约束作为幂等的最后防线。

## 接口一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/persons` | 登记参保人 |
| POST | `/api/persons/{id}/periods` | 登记任职期间（登记号幂等） |
| POST | `/api/persons/{id}/periods/corrections` | 更正历史期间，产生新版本 |
| GET | `/api/persons/{id}/versions` | 期间版本列表（各版本引入/取代的期间） |
| GET | `/api/persons/{id}/versions/{v}/periods` | 指定版本下有效的期间集合 |
| GET | `/api/persons/{id}/versions/{v}/overlap` | 指定版本的重叠处理与折算明细 |
| POST | `/api/persons/{id}/determinations` | 生成待遇核定（锁定当前版本） |
| GET | `/api/persons/{id}/determinations` | 核定快照列表 |
| GET | `/api/persons/{id}/adjustments` | 差额链台账 |

## 常用命令

运行测试：

    ./mvnw clean test

启动服务：

    ./mvnw spring-boot:run
