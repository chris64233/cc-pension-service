# cc-pension-service

参保人任职期间与待遇资料管理服务：登记任职期间、处理期间重叠、按版本核定养老待遇，
并支持历史期间的追溯更正与待遇差额台账。

## 开发环境

- JDK 21
- Maven Wrapper 3.9.9
- Spring Boot 4.1.1

迁移项目沿用现有 Spring Boot 版本，其他项目使用上述版本。

## 主要业务规则

### 期间登记与幂等

- 参保人可登记多个任职期间，每个期间包含单位、起止日期（闭区间）和计入比例 `(0, 1]`。
- 登记号 `(personId, registrationNo)` 唯一，是幂等键：重复提交同一登记号直接返回首次
  生成的版本，不产生新期间、新版本。

### 重叠处理与年限折算

- 相互重叠的期间不重复累计：将时间轴按所有期间端点切分为基本区间，每个区间取覆盖它的
  所有期间的**最大计入比例**；相邻且比例相同的区间先合并，再统一折算，避免分段舍入累积误差。
- 折算规则：分段年限 = 天数 × 计入比例 / 365，保留 4 位小数（HALF_UP）；累计年限为各分段之和。

### 服务年限版本

- 每次登记或更正在参保人维度生成一个单调递增的版本（`ServiceYearVersion`），
  版本保存当时的合并分段与累计年限，写入后不可修改。

### 待遇核定（快照）

- 核定时锁定当前最新版本，将累计年限、计发比例、待遇基数与分段明细完整拷贝为
  不可修改快照（`BenefitAssessment`），后续期间更正不影响已生成的核定。
- 待遇规则：计发比例 = 累计年限 × 1%（上限 90%）；待遇基数 = 参考工资 × 计发比例
  （2 位小数，HALF_UP）；月待遇 = 待遇基数。金额一律使用 `BigDecimal`。

### 追溯更正与差额台账

- 更正不修改原期间记录：原记录标记 `superseded`，更正内容作为新记录生效并产生新版本；
  `voided=true` 表示作废该期间。只能更正当前生效（未被取代）的记录。
- 核定后发现历史期间错误时，通过更正产生新版本，再按最新版本重算待遇并与原核定比较，
  差额（正 = 补发 `SUPPLEMENT`，负 = 追回 `RECOVERY`）形成独立台账记录
  （`BenefitAdjustment`），原核定不被覆盖，多次更正形成差额链。

### 并发控制

- 同一参保人的登记、更正、核定、差额计算均先对参保人账户行加悲观写锁串行化：
  并发新增/更正重叠期间不会重复累计年限；核定与更正并发时，核定只基于一个完整版本。
- 参保人账户首次创建在独立事务（REQUIRES_NEW）中完成并提交，JVM 内互斥 +
  主键唯一约束兜底，避免并发初始化冲突。

## API 概览

基础路径 `/api/persons/{personId}`：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/periods` | 登记任职期间（登记号幂等），返回新版本 |
| POST | `/corrections` | 更正/作废历史期间，返回新版本 |
| POST | `/assessments` | 按最新版本核定待遇，生成快照 |
| POST | `/adjustments` | 基于最新版本重算，生成差额台账 |
| GET | `/periods` | 期间登记记录（含已取代/作废） |
| GET | `/versions`、`/versions/{versionNo}` | 年限版本与合并分段 |
| GET | `/assessments`、`/assessments/{id}` | 核定快照 |
| GET | `/adjustments` | 差额台账链 |
